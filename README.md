# CCTasks — анализ задач системы реального времени

Консольное приложение на **C# / .NET Framework 4.8** для практической работы № 1 «Классификация систем реального времени и расчёт требуемого времени реакции» по дисциплине «Вычислительные системы реального времени».

Программа анализирует задачи промышленного контроллера линии: аварийную остановку, опрос датчиков, воздействие на привод, обновление индикации и журналирование. Параметры задач считываются из CSV, а параметры вычислительной системы вводятся в консоли.

## Возможности

- Определение класса системы: жёсткого или мягкого реального времени.
- Определение типа дедлайна каждой задачи.
- Расчёт временного запаса и проверка условия `C ≤ D`.
- Поиск критической задачи среди жёстких задач.
- Расчёт требуемого времени реакции и суммарной загрузки процессора.
- Классификация архитектуры по количеству процессоров и наличию сети.
- Вывод таблицы результатов и итогового заключения.

Класс жёсткости каждой задачи задаётся во входном файле. Программа использует эти значения при анализе системы, а не определяет их автоматически по времени выполнения.

## Требования

- Windows с установленным .NET Framework 4.8 для запуска приложения.
- Visual Studio с компонентами разработки приложений .NET и поддержкой целевой платформы .NET Framework 4.8 для сборки.

Сторонние NuGet-пакеты не используются.

## Сборка и запуск

1. Скачайте проект или клонируйте репозиторий.
2. Откройте файл `CCTasks.sln` в Visual Studio.
3. Соберите решение в конфигурации **Debug**.
4. Убедитесь, что в каталоге `CCTasks/bin/Debug` находится файл `tasks.csv`. Если его нет, создайте его по примеру ниже.
5. Откройте PowerShell в папке, содержащей `CCTasks.sln`, и выполните:

```powershell
Set-Location .\CCTasks\bin\Debug
.\CCTasks.exe
```

6. Введите количество процессоров и ответьте на вопрос о наличии сети:

```text
Количество процессоров: 1
Есть сеть? (да/нет): нет
```

После вывода результатов приложение ожидает нажатия клавиши.

**Путь к данным:** текущая реализация читает `File.ReadAllLines("tasks.csv")`. Поэтому CSV должен находиться в рабочем каталоге процесса. При запуске через Visual Studio проверьте рабочий каталог в параметрах отладки проекта. Автоматическое копирование CSV при сборке в текущем `.csproj` не настроено.

## Входные данные

Файл `tasks.csv` имеет кодировку UTF-8 и разделитель `;`. Первая строка — заголовок, последующие строки — задачи. Все значения времени задаются в миллисекундах.

```csv
Name;Hardness;C;D;T
Аварийная остановка;жесткое;1;5;5
Опрос датчиков;жесткое;2;20;20
Воздействие на привод;жесткое;2;10;10
Обновление индикации;мягкое;8;100;100
Журналирование;мягкое;40;500;500
```

| Поле | Значение |
| --- | --- |
| `Name` | Название задачи |
| `Hardness` | Класс жёсткости задачи |
| `C` | Время выполнения |
| `D` | Относительный дедлайн — допустимый срок завершения после активации |
| `T` | Период активации |

Числа читаются с культурой `ru-RU`: для дробных значений используется запятая, например `1,5`.

Для жёстких задач необходимо точное значение **`жесткое`** — в нижнем регистре и с буквой `е`. Значение `жёсткое` текущий код не распознаёт как жёсткий класс. Другие значения не участвуют в выборе критической жёсткой задачи; проверка допустимых названий классов не реализована.

## Правила расчёта

### Временной запас

```text
L = D − C
```

При `L ≥ 0` в столбце «Выполнимо» выводится «Да», при `L < 0` — «Нет». Эта проверка относится к собственному времени выполнения задачи и не учитывает ожидание процессора или вытеснения.

### Тип дедлайна

| Условие | Тип |
| --- | --- |
| `D = T` | Неявный |
| `D < T` | Ограниченный |
| `D > T` | Произвольный |

Равенство проверяется первым, поэтому категории в выводе не пересекаются.

### Класс системы и критическая задача

Если есть хотя бы одна задача с `Hardness = "жесткое"`, система относится к жёсткому реальному времени. В противном случае — к мягкому.

Критическая задача имеет минимальный `L` среди жёстких задач. При одинаковом запасе выбирается первая по порядку в файле. Если жёстких задач нет, критическая задача отсутствует.

### Требуемое время реакции

```text
Rтреб = min(D) среди жёстких задач
```

Если жёстких задач нет, минимум рассчитывается по всем задачам. Это требование к времени реакции системы, а не измерение скорости работы приложения.

### Загрузка процессора

```text
U = Σ(Ci / Ti)
```

Для одного процессора `U ≤ 1` — необходимое, но в общем случае недостаточное условие выполнимости расписания. При нескольких процессорах требуется учитывать распределение задач: само по себе `U > 1` ещё не означает перегрузку всей системы.

### Архитектура

| Наличие сети | Количество процессоров | Класс по принятому правилу |
| --- | --- | --- |
| Есть | Любое допустимое | Распределённая |
| Нет | 1 | Однопроцессорная |
| Нет | Больше 1 | Многопроцессорная |

## Пример результатов

Для приведённого CSV, одного процессора и отсутствия сети ожидаются следующие результаты:

| Задача | C, мс | D, мс | T, мс | L, мс | C ≤ D | Тип дедлайна |
| --- | ---: | ---: | ---: | ---: | :---: | --- |
| Аварийная остановка | 1 | 5 | 5 | 4 | Да | Неявный |
| Опрос датчиков | 2 | 20 | 20 | 18 | Да | Неявный |
| Воздействие на привод | 2 | 10 | 10 | 8 | Да | Неявный |
| Обновление индикации | 8 | 100 | 100 | 92 | Да | Неявный |
| Журналирование | 40 | 500 | 500 | 460 | Да | Неявный |

Расчёт загрузки:

```text
U = 1/5 + 2/20 + 2/10 + 8/100 + 40/500 = 0,66 = 66 %
```

Ожидаемое заключение программы:

```text
Класс системы: жесткого реального времени.
Архитектура: однопроцессорная.
Критическая задача: Аварийная остановка, запас: 4 мс.
Требуемое время реакции: 5 мс.
Загрузка: U = 0,66 (66%).
Условие U <= 1 выполнено.
Для всех задач C <= D. Для гарантии соблюдения дедлайнов нужен анализ расписания.
```

## Структура программы

Пути приведены относительно папки с `CCTasks.sln` в исходном проекте.

| Файл | Назначение |
| --- | --- |
| `CCTasks.sln` | Решение Visual Studio |
| `CCTasks/CCTasks.csproj` | Настройки сборки и целевой платформы |
| `CCTasks/Program.cs` | Точка входа, чтение данных, расчёты и вывод |
| `CCTasks/RealtimeTask.cs` | Модель задачи |
| `CCTasks/App.config` | Конфигурация приложения |
| `CCTasks/bin/Debug/tasks.csv` | Исходный набор задач в переданном проекте |

`RealtimeTask` хранит свойства `Name`, `Hardness`, `C`, `D`, `T` и вычисляемые поля `deadlineType`, `L`, `signFeasibility`. Для набора задач используется `List<RealtimeTask>`.

| Метод | Назначение |
| --- | --- |
| `Main` | Организация последовательности работы |
| `ReadingTask` | Чтение CSV и создание объектов задач |
| `ReadSystemParameters` | Ввод количества процессоров и наличия сети |
| `DeterminingTypeDeadline` | Определение типов дедлайнов |
| `CalculatingTaskStock` | Вычисление временных запасов |
| `TaskClassification` | Определение класса системы |
| `SearchCriticalTask` | Поиск критической жёсткой задачи |
| `RequiredReactionTime` | Расчёт требуемого времени реакции |
| `Utilization` | Расчёт суммарной загрузки |
| `ClassifyArchitecture` | Определение архитектурного класса |
| `PrintTasks` | Вывод таблицы задач |
| `PrintConclusion` | Вывод итогового заключения |

## Особенности и ограничения

- Количество процессоров проверяется: требуется целое число не меньше 1. Для наличия сети принимаются ответы «да» и «нет» без учёта регистра и крайних пробелов.
- Пустые строки CSV пропускаются. Если задач нет, программа выводит сообщение и завершается после нажатия клавиши.
- Отсутствие файла, неверное количество столбцов и ошибки преобразования чисел не обрабатываются.
- Корректность диапазонов `C`, `D`, `T` не проверяется. Для расчётов следует задавать конечные значения `C ≥ 0`, `D > 0`, `T > 0`.
- JSON, выбор пути к CSV через аргументы командной строки и моделирование расписания не реализованы.
- Приложение выполняет предварительный анализ временных ограничений. Оно не учитывает блокировки, вытеснения, накладные расходы ОС и сетевые задержки.

## Оформление репозитория для сдачи

Задание предусматривает папки `src/` для кода, `data/` для исходных данных и `docs/` для отчёта. В исходном проекте используется структура решения Visual Studio, описанная выше.

При подготовке репозитория к сдаче следует перенести решение и проект в `src/`, сохранить `tasks.csv` в `data/`, а отчёт — в `docs/`. После переноса данных нужно настроить их копирование в рабочий каталог приложения или изменить путь чтения в коде. Простое перемещение CSV в `data/` не изменит поведение `ReadingTask`.

Служебные папки `.vs/`, `bin/` и `obj/` следует исключить через `.gitignore`, предварительно сохранив исходный CSV вне `bin/`. История коммитов должна отражать реальные этапы работы над проектом.
